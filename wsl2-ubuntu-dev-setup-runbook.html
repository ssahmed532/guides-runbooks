Runbook · Windows 11 · WSL2 · Ubuntu 26.04 LTS · Claude Code

WSL2 Developer Runbook

A fresh Ubuntu 26.04 LTS instance on WSL2, set up for development with Claude Code running inside Linux: back up and remove any old instance, bring WSL itself up to date, then build the new one. Every developer tool (Git, SSH, Node.js, Python, Claude Code, containers, cloud CLIs) is installed and runs inside Linux; Windows only supplies WSL, a terminal, and a browser for one-time sign-ins. Every step keeps Microsoft's defaults unless a measurement or an official recommendation says otherwise, and each change has an undo.

Sequence at a glance

Order matters in three places. The old instance is backed up before it is removed, because removal deletes its disk. WSL is brought up to date before the new distro is created, and .wslconfig is written before that too, so the new disk is created sparse. The service trim runs before the toolchains, so the boot-time baseline is clean when you measure it.

The first table is the single biggest factor: Linux tools working on files under /mnt/ are 100 to 300 times slower than on the Linux disk. Microsoft's guidance is the same: store files on the file system of the tools that use them (References).

What Windows must provide

The setup is Linux-native: every tool below is a Linux binary installed with Linux package managers, configured under /home, and authenticated from the Linux shell. The Windows side shrinks to this:

Required on Windows

  • Windows 11 (22H2 or later) with Windows Update current
  • WSL from the Microsoft Store (phase 01)
  • A terminal. Microsoft recommends Windows Terminal.
  • A web browser, on this or any other device, for one-time sign-ins. Each sign-in prints a URL or code; nothing connects the Linux tools to a Windows browser.

Not needed on Windows

  • Git for Windows and Git Credential Manager: Git and SSH run in Linux (phase 08)
  • Node.js, Python, uv: installed in Linux (phases 10–11)
  • Claude Code for Windows: the Linux build runs in WSL (phase 12)
  • GitHub CLI and Azure CLI for Windows (phase 13)
  • Docker Desktop: Docker Engine runs in Ubuntu (phase 15)
  • VS Code: optional (phase 14)

Windows copies of these tools can stay installed for Windows work. Phase 16 stops WSL from seeing them, so nothing in Linux runs a Windows copy by accident.

00

Back up and remove an existing instance

optionalMicrosoft

Skip this phase on a machine with no distro to replace. wsl --unregister deletes the distro's disk with all its files, settings and software, and cannot be undone. The export in step 2 is your only way back.

Unregister only the distro you are replacing. wsl -l -v may also list docker-desktop: that one belongs to Docker Desktop, so leave it alone.

1. Find work that exists only in this distro

Inside the old distro, list repositories with uncommitted changes or commits that were never pushed. Push or copy anything you need.

Old distro · bash 
for d in $(find ~ -maxdepth 4 -name .git -type d -prune 2>/dev/null); do
  r=${d%/.git}; echo "== $r"
  git -C "$r" status --short --branch | head -5            # uncommitted changes
  git -C "$r" log --branches --not --remotes --oneline | head -5   # commits on no remote
done

Also note the files you will want in the new instance: ~/.ssh/, ~/.gitconfig, ~/.claude/ and ~/.claude.json (Claude Code settings, MCP servers, session history), your shell config files, and /etc/wsl.conf.

2. Export a full backup

PowerShell 
$env:WSL_UTF8 = 1                   # readable wsl.exe output
wsl -l -v                           # confirm the exact name of the distro to replace
$old = 'Ubuntu-24.04'               # <- the distro you are replacing
$bak = 'D:\WSL-backup'              # <- a drive with room for the distro's used space
New-Item -ItemType Directory -Force $bak | Out-Null

wsl --shutdown
wsl --export $old "$bak\$old-$(Get-Date -Format yyyy-MM-dd).tar"
Get-ChildItem $bak                  # the .tar is roughly the size of the distro's used space

--format tar.gz produces a smaller file at the cost of a slower export.

The archive contains everything in the distro, including private SSH keys and Claude Code and Git tokens. Keep it on an encrypted drive, and delete it once the new instance passes the Definition of done.

3. Remove the distro

PowerShell 
# record where its disk lives, to check for leftovers afterwards
$base = (Get-ChildItem HKCU:\Software\Microsoft\Windows\CurrentVersion\Lxss |
  Where-Object { $_.GetValue("DistributionName") -eq $old }).GetValue("BasePath") -replace '^\\\\\?\\',''
$base

wsl --unregister $old               # permanent: deletes the distro's disk
wsl -l -v                           # the distro is no longer listed
Test-Path $base                     # if the folder remains, check it is empty before deleting it

# older Store-app installs also leave an app behind; list any:
Get-AppxPackage | Where-Object { $_.Name -match 'Canonical|Ubuntu' } | Select-Object Name, Version

If Get-AppxPackage lists an Ubuntu app, uninstall it in Settings → Apps → Installed apps, as Microsoft describes. Newer installs, including this laptop's Ubuntu 24.04, are not Store apps, so nothing is listed. If Windows Terminal still shows a profile for the old distro, delete it in Terminal Settings.

4. Bring selected files across later

After phase 12, copy back only what you need from the archive. Look inside it first, because entry paths start with the old user's home folder:

New distro · bash 
tar -tf /mnt/d/WSL-backup/<file>.tar | grep -E '/\.ssh/|/\.claude' | head -20
mkdir -p /tmp/restore
tar -xf /mnt/d/WSL-backup/<file>.tar -C /tmp/restore <paths from the listing>
# copy what you need into ~, then for SSH keys:
chmod 700 ~/.ssh && chmod 600 ~/.ssh/id_*

Or, to browse the old system as a whole, import the archive as a temporary distro, copy what you need, then remove it: wsl --import Old-Ubuntu C:\WSL\old-ubuntu <file>.tar, then wsl --unregister Old-Ubuntu.

Full platform reset (only if WSL itself is broken)

Removing the WSL package is a separate step from removing a distro, and is not needed for a normal fresh start. Quit Docker Desktop first, because it runs on WSL. Then run wsl --uninstall, followed by phase 01, which reinstalls WSL.

Verify

The .tar backup exists with a plausible size, wsl -l -v no longer lists the old distro, and nothing outside it (such as docker-desktop) changed.

01

Bring Windows and the WSL platform up to date

Microsoft

The new distro runs on whatever WSL version and kernel are installed when it is created. Recent features in this runbook have minimum versions: wsl --manage needs WSL 2.5, built-in containers need 2.9.3, and mirrored networking and DNS tunneling need Windows 11 22H2.

1. Windows itself

Install pending updates in Settings → Windows Update and restart if asked. Then confirm the build:

PowerShell 
systeminfo | Select-String "^OS Name","^OS Version"
# Windows 11 22H2 is build 22621; this laptop showed Windows 11 Pro, build 26200

2. Windows components and the hypervisor

PowerShell (administrator) 
# InstallState 1 = enabled. VirtualMachinePlatform is required for WSL 2;
# Microsoft-Windows-Subsystem-Linux is only needed for WSL 1.
Get-CimInstance Win32_OptionalFeature |
  Where-Object Name -in 'VirtualMachinePlatform','Microsoft-Windows-Subsystem-Linux' |
  Select-Object Name, InstallState

bcdedit /enum | findstr -i hypervisorlaunchtype   # expect: Auto
  • WSL or Virtual Machine Platform missing: run wsl --install --no-distribution in an administrator PowerShell. It turns on the required components without installing a distro. Restart Windows afterwards.
  • hypervisorlaunchtype is Off: run bcdedit /set hypervisorlaunchtype Auto (administrator) and restart.
  • Error 0x80370102 later on: turn on CPU virtualization in the firmware (BIOS/UEFI) settings, following the PC maker's instructions.

3. Store-delivered WSL, updated to the latest release

Microsoft recommends the Microsoft Store version of WSL, which receives updates as soon as they ship. If wsl --version is not recognized, the machine has the old built-in version; wsl --update moves it to the Store version.

PowerShell 
# close every WSL window and quit Docker Desktop first
wsl --shutdown
wsl --update
wsl --version          # WSL version, kernel version, WSLg
wsl --status           # default distro and default version (expect 2)

# the Store package, if you want to see it directly
Get-AppxPackage MicrosoftCorporationII.WindowsSubsystemForLinux | Select-Object Name, Version

Compare the WSL version with the release marked Latest on github.com/microsoft/WSL/releases. On 2026-10-30 that was 3.0.3, the same version installed on this laptop, with kernel 6.18.54.1.

  • Store blocked by policy: Microsoft's command reference lists wsl --update --web-download, which downloads from GitHub instead of the Store. WSL 3.0.3's own wsl --help does not list that option, so check wsl --help on your version. The other route is the installer files attached to the GitHub release.
  • Pre-release builds: wsl --update --pre-release installs a preview version if one exists. Use it only to test a specific fix; a daily-driver laptop should stay on the release marked Latest.
Verify

Windows 11 build 22621 or later; VirtualMachinePlatform is 1; wsl --version matches the latest GitHub release and is at least 2.9.3; wsl --status reports default version 2.

02

Write the global .wslconfig

Microsoft

Do this before installing the distro. sparseVhd only applies to disks created after it is set; with it on, space freed inside Linux goes back to Windows.

PowerShell 
# look first: edit the existing file instead if one is there
Get-Content "$env:USERPROFILE\.wslconfig" -ErrorAction SilentlyContinue

@'
[experimental]
# new distro disks are created sparse, so freed space returns to Windows
sparseVhd=true
'@ | Set-Content -Path "$env:USERPROFILE\.wslconfig"

Microsoft also recommends the WSL Settings app (Start menu) for these settings instead of editing the file by hand. Both write the same file.

Defaults this runbook keeps, and when to change them

SettingDefaultDecision
[wsl2] memory50% of Windows RAMKeep. Set a cap only if Windows runs short while heavy containers run.
[wsl2] processorsAll logical processorsKeep.
[wsl2] swap25% of RAM, rounded up to whole GBKeep.
[experimental] autoMemoryReclaimdropCacheKeep. Cached memory is already returned to Windows. Docker's docs suggest turning it on; it is already on.
[wsl2] networkingModeNAToptional Set mirrored if you need VPN compatibility, IPv6, LAN access to WSL, or 127.0.0.1 from Linux to Windows services. Needs Windows 11 22H2+.
[wsl2] dnsTunnelingtrueKeep. Aimed at VPN compatibility.
[wsl2] vmIdleTimeout60000 msoptional Raise it to avoid the cold start after a minute idle. The VM keeps its RAM longer.
[general] instanceIdleTimeout15000 msKeep. -1 disables distro auto-shutdown.

If you switch to mirrored networking and need inbound connections, Microsoft documents this Hyper-V firewall command (administrator PowerShell):

PowerShell (administrator) 
Set-NetFirewallHyperVVMSetting -Name '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -DefaultInboundAction Allow

Changes to .wslconfig or /etc/wsl.conf apply only after the WSL VM fully stops. Run wsl --shutdown, or wait about 8 seconds after closing every WSL window and confirm with wsl --list --running.

03

Install Ubuntu 26.04 LTS

Microsoft

wsl --install downloads from the Microsoft Store by default; --web-download is the documented way to bypass the Store. Naming the version keeps the result predictable. Distros are per-user installs, so a normal PowerShell is enough.

PowerShell 
# confirm the exact name: on 2026-10-30 the list showed Ubuntu-26.04 "Ubuntu 26.04 LTS"
wsl --list --online

wsl --install -d Ubuntu-26.04

# only if the download hangs at 0.0%
wsl --install --web-download -d Ubuntu-26.04

The first launch asks for a Linux user name and password. They are separate from your Windows account; the user becomes the distro's default user with sudo rights. Nothing shows on screen while you type the password.

optional --location <folder> places the disk on another drive, for example when C: is short of space. On this laptop the drive made no measurable speed difference.

optional If you prefer the Microsoft Store app: search for Ubuntu and select Get on the listing named just Ubuntu (Store ID 9PDXGNCFSCZV). The Store has no separate listing per version; on 2026-10-30 this listing's description said it provides the 26.04.1 LTS release. The distro may then register under a different name (check with wsl -l -v); use that name in place of Ubuntu-26.04 in the commands below.

PowerShell 
# make it the default if other distros exist
wsl --set-default Ubuntu-26.04

# confirm WSL 2 and a sparse disk
wsl -l -v
$vhd = ((Get-ChildItem HKCU:\Software\Microsoft\Windows\CurrentVersion\Lxss |
  Where-Object { $_.GetValue("DistributionName") -eq 'Ubuntu-26.04' }).GetValue("BasePath") -replace '^\\\\\?\\','') + "\ext4.vhdx"
fsutil sparse queryflag $vhd

# if it reports NOT sparse (for example, .wslconfig was written late):
wsl --shutdown
wsl --manage Ubuntu-26.04 --set-sparse true

WSL prints a notice that sparse disks are still experimental. If you see disk problems, turn it off with wsl --manage Ubuntu-26.04 --set-sparse false. Microsoft also warns: never open, move, or edit the files under AppData that hold the distro with Windows tools. Use \\wsl$\Ubuntu-26.04\ to reach Linux files from Windows.

Verify

wsl -l -v lists Ubuntu-26.04 with VERSION 2, and fsutil prints This file is set as sparse.

04

First boot: update and confirm systemd

Microsoft

Windows does not update Linux packages; you do. systemd must be the init process for the service steps that follow.

Ubuntu · bash 
sudo apt update && sudo apt upgrade

cat /etc/wsl.conf          # expect [boot] systemd=true
ps -p 1 -o comm=           # expect: systemd

# baseline before trimming, for comparison in phase 05
systemd-analyze
systemd-analyze blame | head -10

If /etc/wsl.conf lacks the [boot] section, add it with sudo nano /etc/wsl.conf, then run wsl --shutdown from PowerShell and reopen Ubuntu:

[boot]
systemd=true
05

Disable boot services a dev box does not use

measured

The Ubuntu image ships services meant for cloud servers and managed fleets. On this laptop they were the slowest units at boot, with landscape-client alone at 800 ms. The loop disables only units that exist, so it is safe if 26.04 ships a different set. disable is reversible; nothing is uninstalled.

GroupWhat it doesKeep it if
landscape-client, wsl-proCanonical Landscape and Ubuntu Pro for WSL agentsYour org manages WSL through Landscape or Ubuntu Pro
snapd*Snap package daemon (socket, timers, helpers)snap list shows snaps you use

snap list 2>/dev/null     # expect: no snaps installed

for u in landscape-client.service wsl-pro.service \
  snapd.service snapd.socket snapd.seeded.service snapd.apparmor.service snapd.autoimport.service \
  snapd.core-fixup.service snapd.recovery-chooser-trigger.service snapd.system-shutdown.service snapd.snap-repair.timer \
  cloud-init-local.service cloud-init.service cloud-config.service cloud-final.service cloud-init-hotplugd.socket \
  apport.service apport-autoreport.path apport-autoreport.timer apport-forward.socket \
  rsyslog.service; do
  if systemctl list-unit-files --no-legend "$u" | grep -q .; then sudo systemctl disable --now "$u"; fi
done

Leave unattended-upgrades enabled: it applies security updates.

Verify

After wsl --shutdown and reopening Ubuntu: systemctl --failed lists nothing, and systemd-analyze reports a lower userspace time than the phase 04 baseline (here 2.0 s → 0.74 s).

06

Cap the system journal

measured

Without a cap, the journal grew to 654 MB here, 16% of the distro. A drop-in file keeps the package-owned journald.conf untouched, so upgrades do not prompt about it.

Ubuntu · bash 
sudo mkdir -p /etc/systemd/journald.conf.d
printf '[Journal]\nSystemMaxUse=100M\n' | sudo tee /etc/systemd/journald.conf.d/size.conf
sudo systemctl restart systemd-journald
journalctl --disk-usage
Verify

journalctl --disk-usage stays near or below 100 MB.

08

Create SSH keys; configure Git and commit signing

GitHub docsMicrosoft

SSH keys created inside Linux replace Git Credential Manager from Git for Windows: no Windows program sits in the Git path. GitHub takes an Ed25519 key. Azure DevOps accepts RSA keys only (Microsoft recommends 3072 bits), so it gets a second key. Protect both with a passphrase; keychain asks for it once per WSL boot, not on every push.

1. Identity and keys

Ubuntu · bash 
git config --global user.name "Your Name"
git config --global user.email "you@example.com"

ssh-keygen -t ed25519 -C "you@example.com"     # GitHub: ~/.ssh/id_ed25519
ssh-keygen -t rsa -b 3072                      # Azure DevOps: ~/.ssh/id_rsa

2. Tell SSH which key Azure DevOps gets

Azure DevOps accepts only the first key a client offers, and fails without trying others. Pin the RSA key for its host:

Ubuntu · bash 
cat >> ~/.ssh/config <<'EOF'
Host ssh.dev.azure.com
  IdentityFile ~/.ssh/id_rsa
  IdentitiesOnly yes
EOF
chmod 600 ~/.ssh/config

3. One SSH agent for all terminals

Ubuntu's own ssh-agent user service only starts in a graphical desktop session, so it does not run in WSL. keychain starts one agent and every new terminal reconnects to it. Ubuntu's ~/.bashrc already exits early for non-interactive shells, so this line never prompts inside scripts.

Ubuntu · bash 
echo 'eval "$(keychain --eval --quiet id_ed25519 id_rsa)"' >> ~/.bashrc
# open a new terminal: it asks for each key's passphrase once, then
# every other terminal reuses the agent until WSL shuts down
ssh-add -l          # lists both keys

4. Register the public keys

Ubuntu · bash 
cat ~/.ssh/id_ed25519.pub   # GitHub → Settings → SSH and GPG keys → New SSH key (Authentication key)
cat ~/.ssh/id_rsa.pub       # Azure DevOps → User settings → SSH public keys → + New Key

ssh -T git@github.com       # expect: Hi <user>! You've successfully authenticated ...
ssh -T git@ssh.dev.azure.com
# first connection: compare the fingerprint with the one on the Azure DevOps
# SSH public keys page before typing yes. Success prints "Shell access is not supported."

Select the key text and copy it with Ctrl+Shift+C in Windows Terminal. Azure DevOps SSH keys stop working if you go too long without signing in to Azure DevOps on the web (about 30 days, depending on Entra policy), and organization policy can make keys expire.

5. Sign commits with the same Ed25519 key

These are the Linux lines from Sign Your Commits, which explains each step. Its fifth line points Git at Git for Windows' ssh-keygen.exe; leave it out here, because Ubuntu has a single OpenSSH.

Ubuntu · bash 
git config --global gpg.format ssh
git config --global user.signingkey ~/.ssh/id_ed25519.pub
git config --global commit.gpgsign true
git config --global tag.gpgSign true

printf '%s %s\n' "you@example.com" "$(cat ~/.ssh/id_ed25519.pub)" > ~/.ssh/allowed_signers
git config --global gpg.ssh.allowedSignersFile ~/.ssh/allowed_signers

On GitHub, upload the same public key a second time with key type Signing key; GitHub keeps authentication and signing keys separate.

  • Clone with SSH URLs: git@github.com:<org>/<repo>.git and git@ssh.dev.azure.com:v3/<org>/<project>/<repo>. To move an existing clone from HTTPS, run git remote set-url origin <SSH URL>.
  • Azure DevOps does not serve Git LFS over SSH; repositories that use LFS there need an HTTPS remote.
  • For repositories that are also checked out on Windows, set line endings in a .gitattributes file in the repo rather than per machine.
Verify

Both ssh -T tests succeed; ssh-add -l lists two keys; for a test commit, git log --show-signature -1 prints a line starting with Good.

09

Keep code on the Linux disk

Microsoftmeasured

This is the largest performance decision in the runbook (see Why these steps). Claude Code's docs add that search on /mnt/c can return fewer results than expected while claude doctor still reports search as OK.

Ubuntu · bash 
mkdir -p ~/src && cd ~/src
git clone git@github.com:<org>/<repo>.git

Rule: projects edited with Linux tools live under /home/<you>; projects edited with Windows tools stay on a Windows drive. Avoid sharing one working copy between both. To look at Linux files from Windows, type \\wsl$\Ubuntu-26.04\home\<you>\src into the File Explorer address bar.

10

Install Node.js with nvm

Microsoft

A Linux Node.js prevents WSL from picking up the Windows node and npm through the imported PATH, which runs Windows binaries against Linux files and can build native modules for the wrong OS. Microsoft recommends a version manager; Ubuntu's apt Node.js is outdated.

Ubuntu · bash 
# the command as published by Microsoft; the nvm README also publishes a version-pinned URL
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/master/install.sh | bash

# open a new terminal, then:
command -v nvm      # expect: nvm
nvm install --lts
node --version
which node npm      # both must be under ~/.nvm, never /mnt/c

With nvm, global npm packages install without sudo. Never use sudo npm install -g. Claude Code itself does not need Node.js (phase 12 installs a native binary); Node.js here is for your projects.

11

Install uv and a uv-managed Python

Astral docs

Ubuntu's system Python belongs to the OS: leave it alone and never pip install into it. Projects, scripts and CLI tools go through uv with a Python that uv downloads and manages in your home folder. The working rules match the Windows side (see uv-Only Python Playbook).

Ubuntu · bash 
curl -LsSf https://astral.sh/uv/install.sh | sh
echo 'eval "$(uv generate-shell-completion bash)"' >> ~/.bashrc
# open a new terminal, then:
uv --version
uv python install          # latest CPython, managed by uv
uv python list             # shows the managed interpreter next to Ubuntu's /usr/bin/python3

uv installs a versioned executable only, so python3 on PATH still means Ubuntu's copy. Run Python through uv run, uv tool and project environments.

12

Install, sign in to, and sandbox Claude Code

Claude docs

Install Claude Code inside WSL with the native Linux installer and launch it from the WSL terminal, not from PowerShell. The native install updates itself in the background. WSL 2 is the only Windows option where Claude Code's sandbox works.

Install and check

Ubuntu · bash 
curl -fsSL https://claude.ai/install.sh | bash

# open a new terminal so ~/.local/bin is on PATH, then:
which claude        # expect: /home/<you>/.local/bin/claude
claude --version
claude doctor       # install health, settings validation, auto-update status

To follow the slower, more stable release channel instead, install with bash -s stable or set "autoUpdatesChannel": "stable" in ~/.claude/settings.json. Don't install with npm or the Windows npm.

Sign in

Ubuntu · bash 
cd ~/src/<repo>
claude              # follow the browser prompts

If no browser opens, or the browser ends on a localhost connection error: at the prompt press c to copy the login URL, open it in a Windows browser, sign in, and paste the code it shows at Paste code here. If pasting does nothing, use Shift+Insert or right-click in Windows Terminal, or run claude auth login. This copy-URL flow works with any browser on any device, so there is nothing to connect between Linux and a Windows browser.

Turn on the sandbox

Ubuntu · bash 
# Ubuntu 24.04+ AppArmor check for bubblewrap. 0 or "No such file or directory": nothing to do.
# (On this laptop's WSL kernel 6.18 the key does not exist.)
sysctl kernel.apparmor_restrict_unprivileged_userns

# only if it printed 1:
sudo tee /etc/apparmor.d/bwrap > /dev/null <<'EOF'
abi <abi/4.0>,
include <tunables/global>

profile bwrap /usr/bin/bwrap flags=(unconfined) {
  userns,
  include if exists <local/bwrap>
}
EOF
sudo systemctl reload apparmor

Then, inside a Claude Code session, run /sandbox. Or turn it on for every session in ~/.claude/settings.json:

{
  "sandbox": {
    "enabled": true
  }
}

If a sandbox dependency is missing, Claude Code runs commands unsandboxed by default. Set "failIfUnavailable": true inside the sandbox block to make it refuse to start instead.

Verify

claude doctor shows no warnings; /sandbox shows no Dependencies tab; /status shows the account you expect.

13

Install the GitHub and Azure CLIs

GitHub docsMicrosoftoptional

Claude Code calls gh for pull requests and issues, and az for Azure work. Installed from their vendors' signed apt repositories, both update with sudo apt upgrade, and neither depends on its Windows copy. Install only the ones you use.

GitHub CLI

Ubuntu · bash 
(type -p wget >/dev/null || (sudo apt update && sudo apt install wget -y)) \
	&& sudo mkdir -p -m 755 /etc/apt/keyrings \
	&& out=$(mktemp) && wget -nv -O$out https://cli.github.com/packages/githubcli-archive-keyring.gpg \
	&& cat $out | sudo tee /etc/apt/keyrings/githubcli-archive-keyring.gpg > /dev/null \
	&& sudo chmod go+r /etc/apt/keyrings/githubcli-archive-keyring.gpg \
	&& sudo mkdir -p -m 755 /etc/apt/sources.list.d \
	&& echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" | sudo tee /etc/apt/sources.list.d/github-cli.list > /dev/null \
	&& sudo apt update \
	&& sudo apt install gh -y

Install Docker Engine inside Ubuntu

Docker docsoptional

Docker's own Linux engine, from Docker's apt repository, running under systemd in the distro: no Windows application involved. Docker lists Ubuntu 26.04 (Resolute) as supported. A fresh distro has none of the conflicting packages; on an older one, follow the "Uninstall old versions" step on Docker's page first.

Ubuntu · bash 
sudo install -m 0755 -d /etc/apt/keyrings

sudo chmod a+r /etc/apt/keyrings/docker.asc

sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update

sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo docker run hello-world

Run docker without sudo

Ubuntu · bash 
sudo groupadd docker            # may report that the group already exists
sudo usermod -aG docker $USER

Docker states that the docker group grants root-level privileges. Docker also documents a rootless mode that avoids this. Docker also warns that published container ports bypass firewall rules.

The engine starts with the distro. If it slows WSL start-up noticeably, compare systemd-analyze blame before and after installing it.

Alternatives that depend on Windows

  • Docker Desktop (Windows app): Settings → Resources → WSL Integration → turn on Ubuntu-26.04. Docker requires removing any engine installed inside the distro first, so choose one or the other.
  • wslc (ships with WSL 2.9.3+): Microsoft's tutorial runs it from PowerShell, for example wslc run --rm hello-world. .wslconfig does not configure it.

Keep project files on the Linux disk with every option. Microsoft's container tutorial states that files on the Windows drive "significantly slow things down".

Verify

Stop importing the Windows PATH

measured

By default WSL appends every Windows PATH folder to Linux, so a missing Linux tool silently falls through to its Windows copy. With every tool now installed in Linux, nothing here needs that. Turning it off removed 34 Windows entries on this laptop and cut the lookup of a missing command from 0.26 s to under 0.01 s.

Turn it off (recommended for this setup)

  • Only Linux binaries run by name, so a missing tool fails loudly instead of running its Windows copy.
  • Shorter PATH; typos, tab completion and command -v checks no longer scan dozens of Windows folders.
  • Windows programs still run by full path, for example /mnt/c/Windows/explorer.exe .

Keep the default

  • Choose this if you call Windows programs by name from Linux, such as explorer.exe, clip.exe or code.
  • Claude Code's install troubleshooting page advises against turning the import off, because Windows programs then no longer run by name. In this setup Claude Code runs no Windows programs, and its sign-in uses the copy-URL flow (phase 12).

Edit both files inside Ubuntu with nano. Do not pipe text into them from PowerShell; see Gotchas. The ~/.profile part is only needed if you use VS Code (phase 14).

Ubuntu · bash 
sudo nano /etc/wsl.conf
# add:
[interop]
appendWindowsPath=false

nano ~/.profile
# add at the end, to keep the VS Code launcher:
if [ -d "/mnt/c/Program Files/Microsoft VS Code/bin" ] ; then
    PATH="$PATH:/mnt/c/Program Files/Microsoft VS Code/bin"
fi
PowerShell 
wsl --shutdown
Verify

In a new Ubuntu terminal: echo "$PATH" | tr ':' '\n' | grep -c '^/mnt/' prints 1, and command -v code still resolves.

Gotchas

Most of these came up during the 2026-10-30 session that this runbook is based on.

  • Piping a script into WSL from PowerShell can stop it partway, with no error. With … | wsl bash -s, any Windows program the script calls (such as npm or az through the imported PATH) reads the rest of the script from stdin, so the remaining commands never run. Copy the script into the distro and run it with stdin from /dev/null.
  • Text piped from PowerShell into a Linux file gains Windows line endings. The symptom is $'\r': command not found on every login. Edit Linux files with nano inside Ubuntu, or remove the carriage returns with sed -i 's/\r$//' <file>.
  • wsl.exe output looks spaced out or garbled in PowerShell. It writes UTF-16 by default. Set $env:WSL_UTF8=1 before running it in scripts.
  • Configuration changes seem to have no effect. The VM was still running. Run wsl --shutdown, or confirm with wsl --list --running.
  • Endpoint protection slows file work on the Windows side, not inside the Linux disk. Here, native Windows file creation on E: was 70 times slower than on the Linux disk, while the Linux disk wrote at about 950 MB/s. Scan exclusions are a security decision for InfoSec, not part of this runbook.
  • Ubuntu's built-in ssh-agent service never starts in WSL. Its user unit has ConditionPathExists=/etc/X11/Xsession.options, so it waits for a graphical desktop session that WSL does not start. That is why phase 08 uses keychain.
  • Slow DNS may not be a WSL problem. Lookups taking 1–2 s here were equally slow on Windows. Test from both sides before changing dnsTunneling or networkingMode.
